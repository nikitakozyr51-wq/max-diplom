# Как перенести диплом на свой ПК

Перенос подготовлен 21 октября 2026 года. Рабочий текст: введение, глава 1, подразделы 2.1–2.2. Последняя опубликованная версия диплома — 30 страниц с титулом, содержанием и источниками. Во время переноса содержание диплома не изменялось.

## Начать работу в новой папке

1. Скачайте полный архив `max-diplom-complete-2026-10-21.zip` из сообщения о переносе. Распакуйте его, например, в `C:\Diplom`. Работайте с извлечённой папкой, а не внутри ZIP.
2. Откройте `docs/Working_Draft_Zhurilov_RoRo.docx` в Word. Готовый PDF находится рядом. Для чтения и обычного редактирования Python и облачная среда не нужны.
3. В Codex на ПК или в редакторе с Codex выберите эту папку как локальный проект и создайте новый чат.
4. Вставьте текст из `PROMPT_FOR_NEW_CHAT.txt`. Агент прочитает `NEW_CHAT_CONTEXT.md` и продолжит с сохранённого этапа. Работа через облачную задачу для этого не требуется.

Если вы создаёте проект в обычном ChatGPT, он не получает доступ к папке на диске автоматически: прикрепите `NEW_CHAT_CONTEXT.md`, актуальный Word, план и необходимые требования вуза. Для работы непосредственно с папкой удобнее локальный Codex или расширение редактора.

## Что лежит в папке

| Путь | Содержимое |
| --- | --- |
| `docs/` | Общий Word/PDF, краткое содержание и подробный план |
| `research/manuscript.json` | Исходник, из которого собран текущий Word/PDF |
| `working-draft.md` | Текст для чтения, включая библиографию |
| `research/sources.csv`, `research/evidence.csv` | Источники, проверенные положения и ограничения |
| `tools/`, `build_local.py` | Переносимый сборщик и официальный титульный шаблон |
| `NEW_CHAT_CONTEXT.md`, `AGENTS.md` | Текущий контекст и правила продолжения |
| `materials/research/` | Все сохранённые исследовательские файлы облака, источники, проверки, ARS, исходный сборщик |
| `materials/memory/` | Требования вуза, карты требований и исторические заметки |
| `materials/attachments/` | Все четыре исходных пользовательских вложения |
| `materials/git-history.bundle` | Резервная копия всех доступных Git-коммитов и веток на момент переноса |
| `TRANSFER_MANIFEST.json` | Перечень файлов полного архива с SHA-256 |

Папка `materials/` и манифест присутствуют в **полном личном архиве**. В обычном GitHub Download ZIP содержится рабочая часть проекта, без полных сторонних источников и личного диплома-образца. Старые заметки сохранены без переписывания; их пути вида `/workspace/...` описывают прежнюю среду. Соответствия: `max-diplom` → корень этой папки, `max-diplom-research` → `materials/research`, `max-diplom-memory` → `materials/memory`, `attachments` → `materials/attachments`.

Сохранены все доступные файлы работы. Удалённый прежний чат восстановить из файлов нельзя; его известный контекст собран в памятке. Служебные настройки облака и учётные данные не нужны для локальной работы и в архив не включены.

## Проверить полный архив

Если установлен Python, откройте терминал в распакованной папке и выполните:

```text
python verify_transfer.py
```

На Windows вместо `python` можно использовать `py`. Проверка сверит каждый файл с манифестом. После собственных правок несовпадение хеша соответствующего файла ожидаемо. Дополнительные файлы не считаются повреждением переноса.

## Пересобирать Word и PDF автоматически — по желанию

Нужны Python 3.10 или новее и LibreOffice. Для точного шрифта PDF нужен установленный Times New Roman. Word можно редактировать вручную без этих инструментов.

Windows, терминал в папке проекта:

```text
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe build_local.py --check
.venv\Scripts\python.exe build_local.py
```

Затем для повторной сборки можно открывать `build_windows.cmd` двойным щелчком. LibreOffice определяется автоматически в стандартном месте установки. При нестандартной установке задайте переменную `SOFFICE` с полным путём к `soffice.exe`.

macOS/Linux:

```text
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python build_local.py --check
.venv/bin/python build_local.py
```

Сборка читает `research/manuscript.json` и создаёт Word, PDF и отчёт в `docs/`. Она заменяет текущие файлы: перед сборкой сохраните ручные правки Word и перенесите их в исходник. Для отдельной копии: `python build_local.py --output exports/Review_Copy`.

Проверено в этой Linux-среде, в том числе из папки с пробелами и кириллицей. На Windows/macOS запуск в данной сессии не выполнялся; пути LibreOffice и временные каталоги адаптированы для этих систем. Пагинация может измениться при другом шрифте или редакторе.

## История версий и GitHub — по желанию

Проект работает без Git и GitHub. При желании все доступные исходные коммиты можно восстановить в отдельную папку:

```text
git clone materials/git-history.bundle restored-history
```

История — снимок на дату переноса, а не подключение к аккаунту. Для дальнейшей публикации потребуется собственная авторизация GitHub на ПК. Полные локальные материалы исключены через `.gitignore`.
